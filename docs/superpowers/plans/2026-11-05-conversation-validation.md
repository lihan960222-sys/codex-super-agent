# Codex Super Agent 手机对话三轮验证 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 由当前执行者在本机顺序推进，不默认增加并行模型代理。

**Goal:** 用人类在 Telegram 中的自然连续对话，验证寻址、执行、控制、恢复和统一交付，完成三轮“完整测试后集中修复”，留下可复现证据。

**Architecture:** 复用 Runtime → Routing/Router → Core/Scheduler/Executor → Delivery 的真实实现，从模拟 Telegram update 注入。语义场景调用真实 Router，代表性执行场景调用真实 Worker；确定性替身仅用于故障及状态机检查，所有结果显式标注层级。线上只做不会抢消息的观测，真实 Telegram 用户收发有独立能力边界。

**Tech Stack:** 本机 Windows、PowerShell、Node.js 24、node:test、node:assert、node:sqlite、现有 Codex App Server Client/Native，无新增测试框架或运行依赖。

**Spec:** `docs/superpowers/specs/2026-11-05-conversation-validation-design.md`

**Scenario catalog:** `docs/superpowers/plans/2026-11-05-conversation-scenarios.md`（120 个基准 + 5 个连续故事）

**状态：仅方案已编写。下列执行步骤均未运行；本文件不是测试报告。**

## Global Constraints

- 本次只交付文档，不改运行代码、不执行三轮、不部署。
- 实施时每轮先完整测试，收齐问题后集中修改，再进入下一轮，共三轮。
- 每轮运行全部 120 个基准场景、固定的高风险重复组，以及该轮新增压力场景。
- 第三轮修复后仍须最终全量回归，不得拿修复前结果验收。
- 按用户指定，三轮测试及最终验收的基线固定为 Router：`gpt-6-luna / medium`，Worker：`gpt-6.1-sol / medium`。仅写入测试设置副本，不改生产设置、不删除生产原生会话；模型不可用时记录阻塞，不自动替换。
- L 组模型切换用例可在自己的隔离夹具中临时改变模型/强度，记录实际调用值；用例结束后恢复上述基线，不影响其他用例。
- 故障只注入测试适配器或独立测试进程，不停止共享 App Server、正式 Bot、正式 Watchdog，不切断整机网络。
- 公开仅提交合成用例、测试代码、脱敏总结和变更记录。
- 错误对象变更、越界文件修改、未经授权复活、伪报执行/完成、串会话均为发布阻断。

## 判定规则（防止测试自欺）

- 自然语言文案不要求逐字相同，目标、动作、事实、保留信息才是断言对象；模型不能当自己结果的唯一裁判。
- 必须由第二条证据交叉验证：SQLite 状态 + 原生 thread/turn；执行成功另加文件内容/哈希；发送成功另加模拟或真实 transport 的明确标记。
- 一次合理澄清可通过，但明确输入重复追问、问同一问题绕圈、提供固定回答后仍不执行都失败。无法唯一定位时正确澄清优于猜测，但永远澄清不是可用性成功。
- N/E 真实调用必须使用上述指定角色模型与强度（L 组隔离切换用例除外，单独记录）。中途更改基线模型、提示词、权限或预算后须作为新基线重新测，不能隐去这一变量。
- 服务鉴权/网络失败可归环境 blocked；不能把工具动作被业务校验拒绝、队列逻辑卡住归为外部环境。
- 记录首次失败与每次重跑，不能只报最后一次通过；测试替身永远正确不代表模型可靠。
- 未运行、跳过、无法读取媒体、需要额外用户侧入口均单列，不放入通过分子。

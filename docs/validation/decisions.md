# 本轮执行取舍与代价

这是执行账本中全部 Ruling 的可公开摘要；私人原始账本保留在本地。没有把取舍隐藏为默认成功。

1. 原生创建 worktree 两次失败后，改用本机 git worktree。保持隔离；代价是手动核验路径/分支。
2. 早期“只交付方案”属于此前规划阶段，后续用户授权启动六项实施任务。代价是必须同时保留此前方案和本次执行证据，不能把规划算作执行。
3. J03 要求真实音频处理与 Router，暂停本身不能要求产生 Worker。代价是 E 组不能一概叫作全部 Worker 回合。
4. 按用户后续要求，将每轮重复注入偏好改为稳定指令前缀和版本缓存，更新旧接口检查。代价是偏好/协议改变会轮换 Router；Worker 历史保留，原生回放仍须证明兼容。
5. 后续需求纳入三个修复批次，未另开第四个功能迭代。代价是最终未通过时保留失败、不自动继续修到“看似通过”。
6. 原 oracle 把同句钢板的运行状态错误归给铝板。保留原始记录、用独立回归修正分句判定、另存重新判定。代价是必须同时审查原判与修正，不能只看最新分数；F01 的停止状态仍按失败处理。
7. Telegram 不确定发送可重复未获确认的一段。验证已确认段落的检查点和不重复任务效果，不承诺恰好发送一次。代价是极端断连时仍可能有重复消息。
8. 第二轮复用 94 个相同修复产品、相同输入/夹具/次数的已完成结果，再补全 91 个缺项。产品和目录哈希须一致，U 表述不继承，汇总拒绝缺项/重复。代价是来源审计更复杂；任何哈希不符不能算完成。
9. 加速仅调整隔离测试并发为 N/F 6、E 2，生产 maxWorkers 仍为 2。代价是不同负载下的时延不能宣称生产提速。
10. 修复二的真实模型复核由紧接的完整第三轮覆盖，避免重复跑同一失败集。代价是单元通过不等于原生成功；第三轮失败照样记录。
11. 全分支独立审阅放在实现结束、最终冻结回放之前。审阅纠正留在最后修复批次，最终测纠正后的代码。代价是后来仅报告/保存变更不再额外派发代码审阅。
12. 修复三的原生效果由最终 173 项、累计失败表述、卡片与新长测证明。代价是最终失败会阻断发布，而不是另加一轮未说明的开发。
13. 实际 Windows Git 运行时没有 Bash 辅助脚本，使用本机 PowerShell/git 生成等效审阅包，校验祖先关系、非空范围、提交/统计/扩展 diff。代价是手动保证与脚本相同的范围保护。
14. 超 50 任务采用程序原子解析 otherTasks 范围，不提高模型读历史/枚举 UUID 预算。明确其他任务授权和已读例外必需；人工停止和完成记录受保护，卡片有成员版本。代价是例外列表仍最多 50，复杂领域筛选不靠这个操作器猜测；原生 100 任务验证仍必需。
15. 为满足用户“以后迭代可溯源”，保留私有账本/证据而不按通用技能清理工作目录。代价是占用本地存储；私人材料不进入公开 Git。
16. Q04 的主题缺失与长测 D 未建成任务造成判定/覆盖争议，保留原始失败，解释争议，不救成通过。代价是分数保守，必须区分产品缺陷和测试设计；其他明确发布阻断仍成立。

独立审阅没有 Minor 或放弃评判项；六项重要发现都进入了一次修复，并用回归和完整检查验证。最终原生失败另列于 `final.md`，没有被这些取舍抵消。

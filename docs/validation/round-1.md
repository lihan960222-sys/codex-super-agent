# 第一轮：手机自然对话隔离验证

2026-11-05。本轮完整测试已结束，随后集中实现第一批修复；尚未部署。真实模型修复复测另行记录，不并入本轮首次结果。

生产逻辑基线 `dcef829`；回放工具提交 `9ee838f`，工具纠错提交 `7146b65`。Router 固定 `gpt-6-luna / medium`，Worker 固定 `gpt-6.1-sol / medium`；模型设置专项在自己的副本中切换。所有数据为合成数据，Telegram 为模拟接收/发送边界；E 类有真实本机原生会话、文件读写与上传字节证据，不能等同手机网络收发验收。

## 数量与判定

完成 185 次场景执行：120 个基准、24 个关键用例各增加两次、5 个连续故事、12 条新表述。验收工具纠错后另做 12 次受影响项回放，替换相同案例的判定，原始记录保留。最终采信口径为 **125 通过、60 失败、0 环境阻塞**；次数不是模型调用次数，也不是 60 个独立根因。

原始报告曾误判 H03 三次及 STORY03：旧会话 ID 没变，但新会话修改了旧文件。新增断言要求没有多建任务、后续原生 turn 发生在原 thread、标记写入目标任务文件，并将原通过改判失败。E03 初始夹具、I05 缺失的回执字段、K02 缺第二张图、O01/R01 未接上的 F 类检查等工具问题分别纠正回放，不算产品缺陷。S06 改按测试开始前钢板文件的 SHA-256 判断文件是否被原样发送。

## 已证实的主要根因

| 根因 | 代表证据 | 本轮末修复方向 |
| --- | --- | --- |
| 同一输入的两个独立创建动作被宿主拒绝 | A04 首次模型给出两个正确 create，随后被迫合并成一任务 | 接受有界的同输入多创建，分别保存范围与回执 |
| 回复直投绕过了控制和新任务判断 | B06、C04、H05；C04 把 completed 重新变成 running，分流调用为零 | 普通追问保留直投；控制、新建、纠正归属先经语义层 |
| 缺单项可恢复暂停，短称校验过严 | D01/F01/F02/N02；正确目标和组合计划因短称被拒 | 独立 pause 目标；多个任务一次校验、原子提交；保留来源与版本检查 |
| 澄清工具不支持“先不操作”，诱发错误选项 | G01、F01 中模型将 pause_all 标成“不操作” | 卡片从实际计划生成说明，宿主提供取消/调整；拒绝无效计划时给清楚纠错原因 |
| 已完成任务的追问被新建会话接走 | H01/H03/T01/STORY03；两次检索已找到目标仍新建 | 明确续作优先规则，并核验真正使用原任务和 thread |
| 恢复操作丢失新增要求 | E03 有效回放；Worker 只收到固定 resume 指令，没有文件追加标记要求 | 将本次授权和附带要求投递到相应任务输入 |
| Router 缺少排队/等待原因 | I02/I03 | 给出已有资源占用和缺失数据等只读事实 |
| 失败输入在后台反复重试且不通知 | J04/K01/L04 | 为媒体、命令错误保存明确状态并反馈，限制重试 |
| 全局偏好自然语言更新没有持久写回 | L05 | 明确偏好更新能力；文件版本缓存、稳定指令前缀、本地规则检查 |
| 设置范围判断错误 | L06 把泛指 Worker 默认模型改成了单个职责覆盖 | 区分角色默认值与明确点名的职责设置 |
| 原生首轮失败后 Router 永久复用不存在的会话 | P03 三次真实本机服务返回 no rollout found | 仅重建 Router 并复用持久状态；不盲目重建 Worker |
| 自然语言审批回复进入了普通任务输入 | M03 | 显式审批关联与一次性决策；过期和停止后拒绝 |
| 停止发生在组织回复后、发送前仍送旧状态 | I05 修正夹具回放 | 发送前再次核验状态和偏好版本 |

图片标记的真实读取/文件修改、三种文档读取、MD 上传以及 PDF/PNG 交付已有通过证据。PDF 已用 pypdf 解析且提取正确标记，PNG 已用 Pillow 验证；上传指固定字节到模拟发送边界。语音实际转写出现同音错字；静音触发重复处理，不能称语音全部通过。

## 第一批修复验证

已加入可失败的回归并实现上述控制、输入、交付与恢复修复；控制澄清新增由实际计划生成的确认/调整/取消按钮，单次审批文本回复绑定原请求。偏好文件按元数据缓存、内容哈希判版本，固定内容只进入 Router 的稳定 baseInstructions；偏好更新仅轮换 Router，不动 Worker 历史。对明确数字上限及明确禁用词作本地检查，不把主观语气冒称为机械保证，也不对每条回复增加一次审核模型调用。自然语言长期偏好通过显式动作写回原文件并保留私有旧版本。

第一批完整 Windows 测试 **230/230** 通过，包含原有兼容性和新增回归。原有“每轮 payload 带 style”和协议版本断言按新接口更新，同时保留对稳定前缀内容、无重复注入、变更轮换的检查。模型缓存命中由原生 tokenUsage 的 cachedInputTokens 观测，不能由文件缓存或单元测试推断。真实模型失败集与邻近反例复测随后执行；通过前不宣称修复验收完成。

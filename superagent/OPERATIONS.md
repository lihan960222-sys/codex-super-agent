# 本机 Telegram 协调服务

手机继续使用原来的 bot。直接描述任务；明确回复任务消息会直接回到原会话，自由文本由 Router 判断。归属不明时会简短询问。不同任务有独立 Codex 会话，同领域只按条件检索知识，不共享全量聊天。

`/settings` 设置；`/model` 分别选 Router、Worker 或职责，选模型后再选思考强度；`/permissions` 选自动或手动。自动指 Codex 原生 auto_review 风险审核，不等于无限权限或保证所有请求获准。设置用于下一次任务执行；正在执行的回合保持原设置。

`/status` 查看进度；回复任务消息说“停止”只停该任务；`/stop` 或“全部停止”暂停全部；明确要求恢复才会恢复。停止不会撤销已经写入的文件。

可以说“停止检查代码和旧项目，启动两项检索任务”，或回复暂停任务说“恢复这个，其他任务保持原状态”。Router 负责理解任务范围，程序统一执行并返回实际状态。“已排队，尚未开始执行”不代表 Worker 已运行。全局暂停期间只启动指定任务时，其他暂停任务及未选中的排队任务保持暂停；“恢复全部任务”不恢复单独停止的任务。

澄清后的“前者”“好”由 Router 结合持久化问题与操作选项判断，无需重复原请求。若旧问题来自升级前版本、确认范围期间任务已变化，可能重新核对一次。重复回复已经处理的问题不会重复执行旧操作。模型仍可能误判自然语言；不明确时会询问。

## 可编辑文件

现有安装目录中的 `superagent-settings.json`：Router / Worker / Watchdog 模型与强度、默认并发数、自动审核方式、主动尝试与上下文预算。每分钟读取，校验失败保留上一有效版本。修改时增加 revision；不修改 outputRoot 以免拆散已有项目。原 config.json 保留账号、代理和媒体工具配置，不应放到共享位置。

`E:\codex_bot\领域_ID\任务\任务ID_标题\`：工作区、产物、进度.md。
`领域_ID\知识库\`：index.md、条目、待核实、历史版本。条目的 superagent-record 注释含完整结构。修改声明、适用条件或证据时保留 id/领域/revision，程序复核后产生新条目和替代关系；随意修改正文会先隔离为待核实，原文不会被覆盖。入库默认静默，未经证实的推测不用于默认知识检索。

## 持久化与恢复

superagent-state/state.sqlite 是事件、任务、职责、消息关联和待发送效果账本；原生 Codex 会话仍在原 CODEX_HOME。不要在服务运行时复制 SQLite 主文件作为完整备份（还可能有 WAL）。停止服务后备份整个 state 目录，或使用 SQLite 在线备份接口。

两个计划任务负责协调服务和独立 Watchdog。连接失败自动重连并核对原生 clientId；确认已接收的任务不重复提交。无法确定是否接收时保留现场并通知，避免重复修改。Watchdog 正常轮询不调用模型，明显无进展才做语义判断，恢复次数有上限。人工停止不会自动复活。

电脑需开机、登录且在线；关机、休眠、代理停机或账号失效时不能即时回复。断网后的 Telegram 消息保存时间受 Telegram 服务限制。机器登录前桌面自动化不可用。

## 边界

这是基于官方 Codex App Server 的自定义客户端；0.166.0 的 app-server 仍标为 experimental。API 更新需要重新验收。文件/桌面资源按任务声明串行调度，目录隔离不是额外的 OS 安全边界，自动审核也可能拒绝危险操作。保留 Windows 和 Codex 自身权限限制。

Telegram 没有发送幂等键：确认丢失时通知可能重复，任务执行另有原生关联核对。模型分流可能误判；可以回复正确任务，或直接纠正归属。共享知识表示有来源的条件性记录，不代表科学结论获得独立验证。主动尝试每次 15 分钟、最多两次重试，源文件的改进留在副本，需决定是否采用。

旧会话无法追加动态工具注册，沿用原上下文并使用受校验的状态/知识请求标记协议；新会话使用动态工具。旧项目源目录不迁移，新产物进入 E 盘。语音与文件上传沿用既有 Whisper/FFmpeg/Telegraf，格式与大小受原媒体工具和 Telegram 限制。

## 回滚

superagent-release.json 记录当前版本、备份路径与入口。不要直接覆盖新账本或把旧 state.json 恢复成最新状态。若新版本尚未接收真实新消息，可停两个计划任务、确认 Node 退出、从该次备份恢复 run.ps1，再启动原 Bridge。若已接收新任务，先保留新账本/原生会话并排空或导出任务，再制定恢复，避免遗漏或重复执行。版本目录和验收证据保留，不自动删除。

## 执行资源说明

独立任务默认使用受限工具，可通过受控文件接口读写自己的工作区和产物；没有命令、电脑控制、浏览器或外部插件能力，也不能自行申请越界执行。需要运行程序、导出 PDF、操作已有项目或桌面时，Worker 自动申请独占执行锁；宿主卸载并续接同一个原生会话后恢复执行能力。无需在手机上手动换上下文。两个独立文件任务可以并发；拥有通用命令能力的任务保守地独占执行资源，因此两个依赖程序的任务会排队。

这是调度/工具能力边界，不是对恶意进程的完整 OS 隔离。高权限动作仍由现有 Codex auto_review 或手机手动审核处理。当前安装的原生默认权限返回只读；有限任务的文件操作由宿主严格校验任务目录、链接和文件大小，避免为简单文件写入开放命令执行。
